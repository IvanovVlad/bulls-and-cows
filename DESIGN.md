# Bulls and Cows - документация по дизайну

## 1. Структуры данных

### 1.1. Состояние игры

Состояние хранится в замыкании `useGameMaster` (`src/useGameMaster.ts`):

- `moves: UserMove[]` - история попыток;
- `activePlayer` - имя игрока, который ходит;
- `gameOver: boolean` - идёт ли игра.

Почему замыкание: переменные скрыты от внешнего кода, менять их можно только
через методы `makeMove`, `reset`, `stop`. Значения отдаются через геттеры
(`get moves()`, `get gameOver()`), поэтому интерфейс всегда читает актуальное
состояние, а не снимок на момент создания.

### 1.2. История попыток

`UserMove = { playerName, guess, result }`, массив `UserMove[]`.

- **Почему массив.** Порядок важен: номер попытки - это позиция в массиве.
  Добавление в конец и обход по порядку - естественные операции для списка
  ходов. `Map` не подходит, так как ключа у попыток нет.
- **Почему иммутабельное добавление.** `makeMove` создаёт новый массив
  (`moves = [...moves, move]`) и не меняет старый. Интерфейс перерисовывает
  таблицу из текущего значения, и случайная мутация не может испортить уже
  показанную историю.

### 1.3. Результат попытки

`GuessResult = { bulls: string; cows: string }`.

Поля - строки из угаданных цифр, а не числа. Количество быков - `bulls.length`,
количество коров - `cows.length`. Такая форма сохраняет сами цифры, что
удобно для отладки и тестов: по результату видно, какие именно цифры
совпали.

### 1.4. Настройки

`useSettings` возвращает объект с полями `base`, `secretLength`, `secret` и
геттерами для них. Методы `setBase`, `setSecretLength` и `regenSecret`
перегенерируют секрет. Это гарантирует, что секрет всегда соответствует
текущим настройкам, и даёт один источник правды для режима и длины.

### 1.5. Набор цифр

`DIGITS: Record<NumberBase, string>`, например `dec → "0123456789"`.

- Строка, а не массив: для проверки используется `includes`, для выбора -
  индексация.
- `Record<NumberBase, string>` требует описать все четыре системы: если
  добавить новую основу в `NumberBase`, TypeScript сразу укажет на
  пропущенный ключ.

### 1.6. Пул при генерации секрета

В `generateSecret` пул - массив символов `[...DIGITS[base]]`. Из него
удаляется каждая выбранная цифра (`splice`), поэтому повторы невозможны без
дополнительной проверки.

### 1.7. Мемоизация и уникальность

- `countPossibleSecrets` кэширует результаты в `Map<string, number>` по
  ключу `base + length`. Поиск по строковому ключу - O(1).
- `isValidGuess` проверяет уникальность через `Set`: размер множества должен
  равняться длине догадки.

## 2. Алгоритмы

### 2.1. `evaluateGuess(secret, guess)`

1. Оба аргумента приводятся к нижнему регистру.
2. `reduce` идёт по символам секрета `v` с индексом `i`.
3. Если `guess[i] === v`, цифра - бык: `bulls += v`.
4. Иначе, если `guess.includes(v)`, цифра - корова: `cows += v`.
5. Иначе цифры нет в догадке, в результат ничего не добавляется.

Почему результат верный. Догадка и секрет не содержат повторов (это
проверяет `isValidGuess`), поэтому каждая цифра секрета даёт ровно один
исход. Проверка на быка идёт первой, поэтому одна и та же цифра не может
попасть и в быки, и в коровы.

### 2.2. `countPossibleSecrets(length, base)`

Количество секретов - это число упорядоченных наборов из `length` различных
цифр, выбранных из `N` цифр системы:

N · (N − 1) · … · (N − length + 1) = N! / (N − length)!

Функция считает это рекурсивно, по одному множителю на уровень:

- `computeCount(length, size) = size · computeCount(length − 1, size − 1)`;
- база: `length = 0` → `1`;
- база: `size < length` → `0` (набрать нужное число различных цифр нельзя).

Результат сохраняется в `memo`. Повторный запрос с тем же `base` и `length`
возвращается из кэша без пересчёта.

Примеры:

- `bin`, `length = 2`: `2 · 1 = 2` (секреты `01` и `10`);
- `dec`, `length = 4`: `10 · 9 · 8 · 7 = 5040`;
- `bin`, `length = 4`: `0` (четыре различные двоичные цифры не существуют).

### 2.3. `generateSecret(length, base, random = Math.random)`

Пул копируется из `DIGITS`. За `length` шагов `random()` выбирает индекс,
`splice` удаляет цифру из пула и добавляет её в результат. Если `length`
больше числа цифр системы, функция бросает ошибку.

### 2.4. `isValidGuess(guess, length, base)`

Проверки идут по порядку, с ранним выходом:

1. длина догадки равна `length`;
2. все символы различны (`Set`);
3. каждый символ допустим для системы (проверка из `createDigitValidator`).

## 3. Сложность

`L` - длина секрета, `N` - число цифр в системе. Для игры `N ≤ 16`, `L ≤ 6`,
поэтому обе величины малы, но в таблице указана асимптотика.

| Функция                | Сложность                                         | Обоснование                                                                                    |
| ---------------------- | ------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `generateSecret`       | **O(L·N)**                                        | Копия пула - O(N). На каждом из `L` шагов `splice` сдвигает до `N` элементов.                  |
| `evaluateGuess`        | **O(L²)**                                         | `reduce` делает `L` шагов, и на каждом `guess.includes` сканирует до `L` символов.             |
| `isValidGuess`         | **O(L·N)**                                        | `split` и `Set` - O(L). Каждая из `L` цифр проверяется через `includes` по строке длиной `N`.  |
| `countPossibleSecrets` | **O(L)** при промахе кэша, **O(1)** при попадании | Рекурсия делает `L` вызовов, каждый - одно умножение. Поиск в `Map` по короткому ключу - O(1). |

## 4. Принципы чистого кода

1. **Единственная ответственность.** Каждый файл решает одну задачу:
   `evaluateGuess.ts` только оценивает попытку, `isValidGuess.ts` только
   проверяет, `createDigitValidator.ts` только создаёт проверку цифр, `main.ts`
   только отображает интерфейс.

2. **Внедрение зависимостей.**
   - `generateSecret(length, base, random = Math.random)` в
     `src/generateSecret.ts`: источник случайности передаётся параметром.
   - `useSettings(options)` в `src/useSettings.ts`: поле `secretGenerator`
     позволяет подставить генератор. Тесты `tests/game.test.ts` так и делают.

3. **Чистые функции.** `evaluateGuess`, `isValidGuess` и `countPossibleSecrets`
   не меняют аргументы, и результат зависит только от входных данных. Кэш в
   `countPossibleSecrets` - единственное скрытое состояние, и оно не влияет на
   результат.

4. **Иммутабельность истории.** `makeMove` в `src/useGameMaster.ts` добавляет
   попытку через `moves = [...moves, move]`, а не через `push`.

5. **Единый источник правды (DRY).**
   - `DIGITS` в `src/generateSecret.ts` используется в `generateSecret`,
     `createDigitValidator` и `countPossibleSecrets`.
   - `createDigitValidator` используется в `isValidGuess.ts` и в геттере
     `inputValidator` в `src/useGameMaster.ts`. Фильтр ввода в `main.ts`
     использует ту же проверку, что и валидация попытки.

6. **Ранний выход (guard clauses).**
   - `generateSecret`: ошибка при слишком большой длине.
   - `isValidGuess`: выход при неверной длине и повторах.
   - `makeMove`: повторная догадка игнорируется.
   - `computeCount`: базовые случаи в начале функции.
   - `countPossibleSecrets`: возврат из кэша до пересчёта.

7. **Понятные имена и маленькие функции.** `switchPlayer`, `checkWin`,
   `computeCount`, `formatResult` (`main.ts`), `renderTime` (`main.ts`). Имя
   функции описывает действие, а не реализацию.

8. **Инкапсуляция.** `useSettings` и `useGameMaster` прячут изменяемое
   состояние в замыкании и отдают только геттеры и методы. Снаружи нельзя
   напрямую поменять `secret` или `moves`.

9. **Разделение логики и отображения.** Игровые функции не импортируют DOM.
   `main.ts` получает состояние через геттеры `gameMaster`, и только он знает
   о `document`. Элементы создаются через `createElement` с
   `textContent`, без `innerHTML`: текст от пользователя не интерпретируется
   как HTML.
